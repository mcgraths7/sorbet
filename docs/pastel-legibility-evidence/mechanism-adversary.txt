SUMMARY: The spec's arithmetic is right; its account of what else has to change is not. Three criticals, all of which would stop the test author or the implementer.

- **Chart gate breaks if `separation` is built as written.** M7 says a view "simulates first", and the only simulation defined returns an 8-bit hex. Today's gate keeps unrounded floats. Routed through the hex, 5 of 10 printed minima change and 4 floors fail (sorbet dark, ocean light, noir light, midnight light). Measured, not reasoned.
- **Two callers are missing from M6.5.** `tools/check-cli.ts:49` and `apps/playground/src/contrast-checks.ts:12` call `measureColors` with two arguments. One throws in CI's `check:cli` step (not in `pnpm test`), the other fails `pnpm typecheck`.
- **`tools/test-contrast.ts` must change and the spec never says so.** It reads `min` off RULES entries, makes about twenty two-argument calls, pins Token Studio's exact source line (line 554) that M6.5 rewrites, and forbids any unlisted file from importing RULES, which the new M9 script must do. Some of these are expected values the implementer may not touch.

Majors:
- A mistyped `tier` on a rule silently drops the rule: it reads the same as "the contract does not hold it".
- M5's "returns (or throws with)" is two behaviours, and the three reports never go through `checkPreset`. A preset with no `contract` at all is unassigned.
- No run-time check on a floor: `min: null`, 0 or a negative number passes every pair.
- A known contract with an empty tier map returns an empty list and "no failures".
- M9.6's OKLab check has nothing to call: no exported function takes Ottosson's XYZ vectors or returns Lab.
- Unknown `kind`/`view` at run time is unassigned, and check-cvd's own names ("protanopia") are not CvdKind values.

What checked out: the M4 table (86 = 54 + 16 + 16, 70 per mode, every tier's count, kind and floor), the 700, all eight APCA values, the tritan matrix, and keeping the instruments out of the barrel.
